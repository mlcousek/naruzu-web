## Internationalisation

English is the source language; Czech is a catalogue keyed by the English text.

- `apps/web/src/locale.ts` is the one place numbers, dates and UI words are formatted. `t("English text", { name })` returns the text in the current language with `{name}` placeholders replaced; the Czech catalogue is typed so a missing key fails type checking. `tr(text)` handles texts that arrive at runtime (package errors, stored notices) and falls back to the English text when there is no entry; `csPatterns` translate sentences that carry numbers.
- Catalogues are split by area under `apps/web/src/messages/` (`cs.ride.ts`, `cs.garage.ts`, ...) and combined in `messages.cs.ts`.
- `setLanguage` updates `<html lang>`; components that show words call `useLanguage()` to re-render.
- Event and race names come from a name table so the beta shows generic names in both languages.
- Proper names (for example race series) stay as published and are not translated.

Checks: `pnpm check:cs` (see [testing](/naruzu-web/docs/dev/testing/)) requires a non-empty Czech entry for every key, equal placeholders in both languages, and scans for English strings that bypass `t()`. New UI text therefore needs a Czech string in the same pull request.

## Accessibility rules

These are enforced by tests or lint, not just advice:

| Rule                                                                                               | Enforcement                                                                                                                 |
| -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| No text smaller than 12 px; use `var(--fs-min)` (0.75rem)                                          | `apps/web/src/fontFloor.test.ts` scans stylesheets                                                                          |
| Touch and click targets at least 44 by 44 px for the covered controls                              | Playwright checks such as `tests/garage-a11y.spec.ts`; CSS uses `min-height: 44px`                                          |
| Text contrast at least WCAG AA (4.5:1, 3:1 for large text) for theme token pairs in dark and light | `apps/web/src/styles/contrast.test.ts` reads token values from the CSS; known sub-AA pairs are pinned and may not get worse |
| No native dropdowns; use Segmented, ChoiceCards, Stepper, FilterChips or PickerSheet               | ESLint `no-restricted-syntax` on `select` in `apps/web/src/**/*.tsx`                                                        |
| Accessibility lint                                                                                 | `eslint-plugin-jsx-a11y` on web components                                                                                  |
| Keyboard operation and visible focus; bottom sheets no wider than the viewport                     | specs such as the career keyboard spec and `tests/fixtures/career.ts` `tabTo`                                               |
| Reduced motion respected                                                                           | specs emulate `prefers-reduced-motion`; the world has a reduced-motion setting                                              |
| Dark and light themes, status in live regions                                                      | career accessibility spec checks live regions and unique control names                                                      |

When you add a control: give it an accessible name, keep it reachable by keyboard, check it in both themes and at 390 px width, and add both language strings.
